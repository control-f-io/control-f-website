Components

Section Header

Mono label left, counter right, hairline underneath. The smallest and most important element in the system: it opens every section and simultaneously says where you are in the document.

Default

Was wir machen 01 / 04 
<div class="cf-section-header">
  <span class="cf-section-header__label">Was wir machen</span>
  <span class="cf-section-header__count" aria-hidden="true">01 / 04</span>
</div>

Which element carries the label

On a real page it is an <h2> with an id, and the <section> around it points at that id with aria-labelledby. The label is the only thing that names the section, so a <span> there leaves the region unnamed and the document with a hole in its outline. All fifteen section headers on the pattern pages are written this way — six of the seven pages carry one; patterns/404.html is the exception, because there the error is the page and it opens on a title rather than on a section. 

<section class="section" aria-labelledby="blog">
  <div class="cf-section-header">
    <h2 class="cf-section-header__label" id="blog">Blog</h2>
    <span class="cf-section-header__count">189 Beiträge</span>
  </div>
</section>
The demos on this site use a <span>, and that is the exception, not the rule. A specimen in a documentation panel is not a section of the page it sits on; an <h2> there would inject a heading into this page's outline that names nothing. Copy the snippet above, not the demo markup — the two differ on purpose, and this note is the only thing stopping them from reading as a disagreement. Until now the Don't list below said the opposite of every shipping page.

The class sets the type and nothing else — no font-size of an <h2> survives it. Being a heading is a fact about the document, not a claim about how big the words are.

Counter variants

There is always a number on the right — but not always the same kind of number.

Both ends of the rule are the same mono label: 11 px, +0.01em, uppercase. Write the counter in ordinary sentence case and let the CSS raise it, the way every other label in the system works — the accessibility tree then still carries 189 Beiträge rather than a shouted string.

Purely decorative counters get aria-hidden="true". “01 / 04” is a visual orientation aid; read aloud it only interrupts. As soon as the counter carries information (“189 Beiträge”) it stays in the accessibility tree.
And that attribute is now what decides whether a counter is checked. A quantity is a promise a reader can act on before scrolling — six questions is a section you read, thirty is one you search — and a wrong one renders exactly like a right one: eleven pixels of mono at the far end of a hairline, correct at every width, in every contrast check, in every screenshot. scripts/check-section-counts.py has held the landing page's five counters to what stands under them since they were found to be four-fifths wrong, and its own register records what it lost when the FAQ moved to Expertise: it could no longer say that the FAQ's counter was true. It then stopped being true in two places at once — this page's Flush demo said 6 Fragen over two entries, and the accordion's own page said the same over four. scripts/check-faq-count.py is the narrow rule that covers the component wherever it stands: a counter above a .cf-accordion that is not aria-hidden is a quantity, and its number is the number of rows.

The action

The fourth form, and the only one that is not a number. The manual draws it once — FAQ on the left of the rule and SEARCH on the right, in the landing-page mockup — and the table above has called it a <button> since it was written. The demo above it drew a <span>, and the stylesheet had no rule for the form at all.

Following either half of that got you nothing. base.css resets <button> to background: none; border: 0; padding: 0 with font: inherit — which is right, and here it meant a button in this slot came out identical to the counter beside it. Measured on Expertise at 1280 px: 40.3 × 15.9 px, rgb(72, 72, 72), no background, no border, no underline. Every other section on the site teaches the reader that this slot is text, so a control that draws as text is a control nobody looks for.

Button or link — the element is not a style choice

A control that changes something on the page the reader is already on is a <button>; a control that takes them to another address is an <a> with an href. Both take the same class, because they look the same and sit in the same slot, and neither is dressed as the other. The two differ under the reader's hands as well as in the accessibility tree — Space operates a button, Enter follows a link — so a link built as a button answers half the keys it is asked.

The target, and why it is drawn rather than padded

11 px of mono in a 16 px line box is 15.9 px tall — and 11 px once the branch in the cap line trims the descent slot off it, which is the direction that matters here. WCAG 2.2 SC 2.5.8 Target Size (Minimum), level AA, asks for 24 × 24 CSS px of pointer target, and neither of the two exceptions that could apply does: the inline exception is for links inside a sentence, and the spacing exception only holds while nothing else lands within 24 px — an accident of whatever the next section ships, not a property of this component.

Padding would meet the floor and move the drawing. This row is align-items: baseline, so padding-block grows the flex line and takes the hairline down with it — and that hairline is the one axis every section on the site shares. So the target is drawn instead: a transparent ::after centred on the text at max(100%, 1.5rem) in both directions. Layout, baseline, row height and the rule's y stay exactly where a counter leaves them, and the target goes from 40.3 × 15.9 to 40.27 × 24. The max() is why there is no number to keep in sync: a long label keeps its own width, a two-letter one is floored, and a change to --text-xs or to the line height cannot walk the target back under the floor. Trimming the slot off this element takes 100% from 15.9 px to 11 and the target does not move: the floor was always the operative half of that max().

“Row height and the rule's y stay exactly where a counter leaves them” was true of the target and false of the type.

The trim is declared for the three occupants of this row together, and it was written for two of them. This row is align-items: baseline, so the header's content box ends at the lowest item's bottom — one untrimmed item holds the whole header's descent slot open on behalf of the two that gave theirs up. Measured on this page before it was fixed: a header ending in a count drew 16.00 px from the label's baseline to its rule and stood 28 px tall; a header ending in an action drew 20.94 px and stood 32.94. The two axes are three rows apart on this page and it is the only page that draws both, which is why nothing had seen it. → scripts/check-cap-line.py

The focus ring is not enlarged with it. :focus-visible draws base.css's outline on the element's own box, which is the text. The ring marks what the reader sees; a ring standing 4 px clear of the glyphs would read as a second box, in a component that has none.
The two counter gates do not read this class, and that is deliberate. check-section-counts.py holds the designed pages' figures to what stands under them and check-faq-count.py holds a quantity above an accordion to the number of rows. An action in the slot is not a count — sharing .cf-section-header__count would have offered both scripts a word to check as a number.
No shipping page carries the action today. Every section header in patterns/ whose right end is occupied carries a quantity, and a quantity is information the mockup's gesture would delete: 11 Fragen tells a reader whether to read the section or search it. The five headers with an empty right end — Expertise's two, the two search pages, and Über uns's team — have no action to offer that the page does not already make elsewhere, and inventing one is the counter rule in different clothes. The form is built, drawn and documented because the manual draws it; it lands the day a section has something to do. That is the standing this system already gives the team strip.

In context

Header, air, content. The header owns the air: --section-header-gap (80 px) sits below the hairline, and nothing on the page sets that distance locally. Measured off both mockups, where it is 88 px at the 1440 frame.

Unsere Werte 6

Wir bauen Code statt PowerPoints.

Wir managen Lösungen, nicht ausschließlich Projekte. Wir haben vor jedem Menschen Respekt und keine Angst vor komplexen Problemen.

The counter here is 6, and it used to be 1 / 6. This demo names a section that exists — Unsere Werte on Über uns — and that section ships a count, not a position, for a reason written into the page: the values track carries a live position in .cf-values__index, and a second frozen copy of it in the header would contradict the moving one the instant the reader scrolls. The mockup draws 1 / 6 there; the implementation does not, deliberately. A documentation example showing the form the named page rejected is the drift this system is most likely to be copied from.

Flush

When the content below is a ruled container — a process card, the accordion, the blog grid — that container's own top border is the header's rule. Add cf-section-header--flush: it drops the gap and its own border, so one hairline does both jobs instead of two sitting 80 px apart. This is how all three appear in the designer's mockups.

Rules

Do

  • Give every section one — including the ones that already have a heading.
  • Keep the label short: two or three words.
  • Span the full content width, not a column width.
  • On dark, set data-theme="inverse"; the rule flips with it.
  • If the right end is a control, use .cf-section-header__action — a <button> when it acts on this page, an <a> when it navigates.

Don't

  • Don't give it a display size — it is 11 px mono at both ends of the rule, whatever element carries it.
  • No second line underneath.
  • Don't invent counters — if there is nothing to count, the right side stays empty. The same holds for the action: an empty right end beats a control with nothing to do.
  • Don't put a control in the slot as a <span>, and don't give a <button> the counter's class — the reset makes both draw as text.
  • Don't repeat it midway through a section.
