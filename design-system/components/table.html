Components

Table

Ruled rows and nothing vertical. A stack of hairlines with mono labels over it — the same three marks the section header and the accordion are made of, arranged to be read across instead of down. Plain <table> markup, no script, no row-as-a-div.

Default

A caption, a head row of mono labels on the strong hairline, body rows on the subtle one. Everything else is the browser's own table layout, which is better at sizing columns than any set of widths we could write.

The caption is the title. Not a heading above the block. A <caption> is the table's accessible name, it is announced when a screen reader lands on the table, and it stays attached to it when the table is moved, quoted or printed. A heading floating above the box is none of those things — it is only near it.
The <span> is what keeps the title on screen. A caption is a child of the table, and the table is the thing that scrolls — so scrolling to the last column used to carry the title off the left edge with it. Measured on datenschutz at 320 px: of a 151.2 px caption, 42.2 px was still inside the box at full scroll. 72 % of the visible title, gone. At a 20 px browser default the scroll range is longer than the caption is wide, so it left entirely.

It was never a screen-reader defect — the caption is still the accessible name, and the region still borrows it. It was the sighted phone reader who scrolled to read column five and lost the line saying what the rows are.

The sticky box has to be one level in. position: sticky on the <caption> itself does nothing, because a table-caption box is not stickyable — measured, still 42.2 px — and giving the caption display: inline-block to make it stickyable drops it into the table's anonymous cell structure and renders it under the head row. A bare <caption> still renders exactly as it always has: the selector is caption > span, so this is an enhancement over the bare markup .cf-prose promises an author, not a new requirement.

Row headers and numeric columns

When the first cell of a row names what the rest of the row is about, it is a header — <th scope="row">, not a <td>. It is drawn in the body face at body size rather than as a mono label: a row header is the row's subject, which is content, and the mono face in this system marks the things that are not prose.

Any column of figures takes .cf-table__num on the head cell and on every body cell in it. That right-aligns the column so the digits stack, which is the whole reason the table sets tabular figures in the first place.

When it is wider than its column

A table is the one block in this system that legitimately outgrows the measure, so it gets a scroll box rather than permission to widen the page. The demo below is capped at 22 rem to force the state at any window size — click it or tab to it, then use the arrow keys.

This section used to claim that what stops the table compressing instead of overflowing is that the column labels do not wrap — that the head row is the floor, and without it the scroll box would be present and permanently unused. That is not true, and it was load-bearing enough to have produced a do/don't of its own.

Measured, as the min-content width of every table in the system with the heads nowrapped and with them allowed to wrap: zero difference on all four of datenschutz's tables and on three of the four demos on this page. The one exception is Angebundene Quellen above, at 15 px. The body cells are the floor everywhere the system actually draws a table — German data words are longer than the labels over them, and INSTANDHALTUNG at 11 px mono is narrower than the same word at 14 px in the cell beneath it.

So the nowrap stays, but for the reason it shares with the section header and the accordion: a label broken over two lines is read as two words. It is a typographic rule about labels, not a mechanism holding the scroll box open. The scroll box engages because the content is wider than the phone. The one place the nowrap does bind is paper, and there it binds the wrong way — see below.

The three attributes are not optional decoration. A scroll box whose children are all plain text has nothing focusable inside it, so a keyboard has no way to reach it and no way to move it: the last column simply does not exist for anyone not holding a mouse. That is a failure of SC 2.1.1 Keyboard, level A, and it is the single most common accessibility defect in responsive table markup. tabindex="0" makes the box a tab stop and arrow-scrollable; role="region" gives it a landmark to be announced as; aria-labelledby pointed at the caption's id gives that landmark its name, so the table is named once and the region borrows it rather than repeating it in an aria-label that would then drift.

The cost is honest and worth stating, and this paragraph used to understate it by four times. It said a keyboard user lands once on something that does nothing. The box is a tab stop even on a wide screen where it does not scroll, and the tables are not spread thinly across the site — they come in runs. Measured on datenschutz at 1280: all four boxes hold 867 px of content in an 867 px box, so none of them scrolls and a keyboard reader takes four dead tab stops in a row on the page the cookie inventory lives on.

The argument still wins, only by less than it claimed. The alternative is a script that measures overflow on load and on resize and adds the attribute conditionally, and this system does not spend a shipping script on a convenience. Four redundant tab stops still beat one unreachable column.

There is no card-per-row transformation at small widths. Turning rows into stacked cards breaks the one thing a table is for — comparing a column down the page — and a display: block table drops the row and column semantics that scope was there to provide. The narrow answer is the same table, scrolled.

On paper

Nothing scrolls a sheet. A scroll box on paper is a crop, so every column past the box's width is not hidden-until-you-drag — it is gone, and it goes silently, mid-word, with no rule or ellipsis to say a column was dropped. Printed through Chromium at a page box narrow enough to force it, the last column's head came out LETZTE from LETZTE SPALTE and its cell came out KENNW from KENNWORTENDE.

This is the failure mode scripts/check-print-fixed.py opens by naming — invisible in every screenshot this repository takes, because every screenshot is screen — and neither gate covers it. That one reads position: fixed; check-overflow-clip.py reads overflow: hidden. This is overflow-x: auto.

Today's tables all fit A4 and print whole — datenschutz's five columns were checked page by page — so this was the latent case, fixed before it landed rather than after. A narrower sheet, a larger print stylesheet, or one more column, and the cookie inventory the site owes under TDDDG § 25 would print with a column missing and no sign that it did.

It takes two declarations, not one. Releasing the crop alone only moves the cut from the box's edge to the paper's. The head row has to be allowed to wrap before the table can compress into the sheet — which is the one place the nowrap above binds, and the one place it must not. 
@media print {
  .cf-table__scroll,
  .cf-prose__table-scroll { overflow: visible; }

  .cf-table thead th,
  .cf-prose thead th { white-space: normal; }
}

On a dark surface

No modifier. Every colour in the component is a semantic token, so the table inverts by being put somewhere inverted — data-theme="inverse", the footer, or the consent dialog, which rebinds the same four rungs itself.

Accessibility

  • Every header cell carries an explicit scope. It is what tells assistive technology whether the cell heads a column or a row, and a table where the association has to be guessed from position is a table read out as a list of unlabelled values.
  • A <caption> on every table, and it is the first child of <table> — that placement is required, not stylistic.
  • The scroll box is focusable, has role="region", and takes its name from the caption. SC 2.1.1, level A.
  • <thead> and <tbody> add no accessibility semantics of their own — they are here for printing and for the head rule. scope is what does the work.
  • No headers/id pairing anywhere. It exists for tables with several header levels, and a table that needs it is a table that should have been split. If two header rows seem necessary, the answer is two tables.
  • Nothing is conveyed by colour or by weight alone: the head is a different face and sits on a heavier rule, and the row header is distinguished by size and weight as well as position.
  • Contrast, measured in the browser against CF-Grau — the dark end of the page wash, so these are the floors and every one of them improves as the wash lightens: body ink and mono head 13.5:1, caption --text-secondary 5.9:1. On the inverse surface the same three are 21:1, 21:1 and 10.5:1. The row rule is a separator rather than a UI contour: the structure is carried by the markup, not by the hairline, so it is not load-bearing for the 3:1 floor.
  • No layout tables. If it is not data, it is a grid.

Rules

Do

  • Caption every table, in words that say what the rows are, and put the line in a <span> so it stays on screen while the table is scrolled.
  • Wrap it in the scroll box with all three attributes, every time — including when you are sure it fits.
  • Make the first column a th scope="row" whenever it names the row.
  • Put .cf-table__num on any column of figures, head cell included.
  • Keep it to four or five columns. Past that it is a report, and a report is a download.

Don't

  • No vertical rules and no boxed grid. The row rule is the whole drawing.
  • No zebra striping. This system draws contours, not fills, and a stripe is a fill doing a hairline's job.
  • No sorting, filtering or pagination inside the component — that is a server's work and a different pattern.
  • Don't turn rows into cards on a phone. It breaks the column comparison the table exists for.
  • Don't set column widths. The browser sizes them better, and a fixed width is the first thing to break in the other language.
  • Don't spend lime in a cell. A table is data, not the screen's one light moment.
